# ReCaLL code experiment

Independent frozen StarCoder2-3B inference experiment. Existing attacks and notebooks are unchanged. Run pretrained inference manually on Kaggle, never locally.

## Method and research provenance

Studied Xie et al., EMNLP 2024, [paper §3, Eq. (2)–(3)](https://aclanthology.org/2024.emnlp-main.493.pdf), and the [official reference `src/run.py`](https://github.com/ruoyuxie/recall/blob/main/src/run.py), [`process_data.py`](https://github.com/ruoyuxie/recall/blob/main/src/process_data.py), and [`eval.py`](https://github.com/ruoyuxie/recall/blob/main/src/eval.py), accessed 2026-10-30. In the reference, `get_ll`/`get_conditional_ll` return negative model mean cross-entropy; `inference` divides conditional LL by unconditional LL. The reference evaluates the ratio directly with member label 1.

For the **same N target IDs** in both branches:

```
LL_u = (1/N) sum_j log p(x_j | baseline preceding tokens)
LL_c = (1/N) sum_j log p(x_j | prefix, baseline preceding tokens)
ReCaLL = LL_c / LL_u = mean_NLL_c / mean_NLL_u
```

Both LLs are negative. Larger ratios are member-like, fixed from the paper; direction is never selected from labels. This is a ratio of mean log likelihoods, not a difference, probability ratio, perplexity ratio, relative percent change, or average tokenwise ratio. Equal N makes the ratio of sums algebraically equivalent. Nonfinite/zero denominators fail; no clipping or epsilon changes the statistic. Prefix tokens never contribute to LL or N.

### Explicit adaptations

* Natural-language WikiMIA/Pythia experiments become source code with frozen `bigcode/starcoder2-3b` and existing SERSEM labels. No original-paper result-equivalence claim.
* The paper fixes a shared concatenation of non-member examples for a dataset. Here the requested policy fixes **one 128-StarCoder2-token, same-language prefix per target**, selected from the complete saved shadow non-member pool. No newline/separator is added outside those 128 IDs, and no synthetic text is generated. Candidate prefix encoding uses `add_special_tokens=False`; candidate target encoding uses baseline `add_special_tokens=True`.
* The reference's unconditioned forward implicitly skips the first input token, whereas its conditioned mask lets the first target token contribute. To meet this experiment's identical-target requirement, the first baseline input token is retained as an unscored anchor in **both** branches. Every subsequent retained baseline ID is scored. No new BOS is invented. If the tokenizer adds BOS it naturally serves as this anchor; otherwise the first code token serves as the anchor. Any later special IDs are retained exactly as the baseline tokenizer produced them. The reference's auxiliary `all_prob` list indexes masked -100 labels, but its ReCaLL scalar uses `-loss`; that auxiliary-list behavior is not reproduced.
* Native autoregressive alignment: logit at position i predicts input ID i+1. Conditioned input is `prefix_ids + baseline_input_ids`, not retokenized concatenated text. Conditioned scored positions start at 129, unconditioned at 1 (zero-based). They contain identical target IDs and identical N.
* Retain the full baseline input span generated by its right-truncated `max_length`. If `128 + baseline_length` exceeds `min(model.max_position_embeddings, tokenizer.model_max_length)`, truncate the candidate tail **in both branches**, never the prefix. Record original, baseline and retained input counts, both truncation counts, N and the scored-ID SHA256. Respect native sliding attention separately from the positional maximum; sliding-window size is recorded. Position IDs remain continuous through native KV-cache forwards.
* T4 implementation: batch one, 256-token forward chunks with native KV cache. FP16 model, FP32 log-softmax, FP64 token-log-probability accumulation. This preserves the statistic and masks, but finite-precision chunked forwards need not be bit-identical to a monolithic FP16 reference forward. Chunking is fixed, not tuned. Hidden states and vocabulary logits are not saved.
* Recalculate **all unconditioned likelihoods**. Existing scalar loss metadata does not prove tokenizer boundary, mask, reduction, precision and span compatibility. Saved losses are never reused.
* Requested reporting uses empirical FPR **<= 1%**. The reference plotting helper uses strict `< .01`; this boundary adaptation is deliberate. No threshold interpolation.

|---|---|---:|---:|
| Shadow/development | shadow_manifest.parquet | 1600 | 80 |
| Validation | fusion_fit_manifest.parquet | 200 | 20 |
| Threshold calibration | threshold_calibration_manifest.parquet | 200 | 20 |

Attach baseline `config.json` and `heldout_test_scores.parquet`. Attach `heldout_adaptive_scores.parquet` only if adaptive paired comparison is wanted; inference does not depend on it. Complete original manifests are always validated **before** smoke selection. No partitions are regenerated. Smoke selection inherits the baseline seed and balances membership within Go, Java, Python, Ruby and Rust. Prefix selection uses **42**, independently of that selection seed. Full preserves original row identities/order. Score every selected partition, including development/validation; only calibration labels set a threshold.

Prefix candidates are solely saved shadow rows with `is_member=0` and official train provenance. The complete 800-row pool is used in both modes (subject to minimum prefix length). No validation, calibration or held-out rows are prefix sources. Pool contents are validated against held-out IDs/hashes via the existing full-partition validator. Non-membership relies on the existing dataset labels, not an independently verified pretraining audit.

For each target, rank eligible candidates by SHA256 of `[42, target_id, target_hash, prefix_source_id, prefix_source_hash]`, then source ID; target labels do not enter. Exclude itself, exact source-content duplicates, wrong languages, short prefixes, duplicate prefix-token hashes, any shared contiguous 32-model-token span, any shared contiguous 20 lexical-token span (whitespace-independent), and complete inclusion of either shorter lexical sequence. Take the first remaining candidate; fail if none. These fixed overlap exclusions are hygiene, not a parameter search. Prefix manifests record source identities, 128 token IDs/hashes, pool fingerprint and rejection counts. The filter rejects substantial exact copying but **cannot certify semantic unrelatedness or detect every renamed clone**. No claim of complete semantic deduplication is made.

`SourceStore.batches` reads only needed identities from existing Arrow caches or remote streaming, validates content SHA256, and stops once needed source positions have been found. Streaming may traverse earlier rows/shards to reach saved positions; it does not materialize full train datasets. Preparation reads complete selected source strings for overlap screening, retaining only selected targets and approved prefix-pool strings in RAM; no full-population index is built here.

## Resume and cache identity

`recall_cache.sqlite` stores checksummed JSON prefix plans and each completed likelihood branch separately. Keys bind exact sample/source identity, source content hash, prefix source/token hash, target ID sequence/hash, model and tokenizer immutable revisions, tokenizer serialization hash, numeric versions, dtype/reduction, context, native model config, scoring policy, pool provenance, and source hashes. Labels are excluded from inference identity and prefix ranking. SQLite uses synchronous FULL transactions and DELETE journals. An already valid branch causes zero additional model calls; partial-pair resume computes only the missing branch. A forward interrupted before commit must be repeated. A complete plan cache skips source iteration and a complete LL cache skips target construction. Metadata/tokenizer/cache verification still runs.

Persist **all OUT files** with Kaggle Save Version with outputs. Same-run resume: attach saved OUT, keep MODE/RUN_ID and scientific settings, set `RESUME_FROM` to saved OUT. Changed execution identity fails. Smoke-to-full: new full RUN_ID and `RESUME_FROM=''`; point `CACHE_REUSE_FROM` at saved smoke database. Compatible entries are copied; other keys are harmless and unused. Rebuilding changed source invalidates caches by design. No automatic cache deletion. Stop active cells before copying a database; preserve any transaction journal after interruption. Atomic JSON/Parquet replacement and per-branch transactions protect completed work. `run_manifest.status='scoring'` distinguishes incomplete runs from completed evaluation.

## Evaluation and output

Threshold: maximize calibration TPR among empirical thresholds with FPR <= .01; ties follow conservative descending ROC threshold order. If no finite eligible threshold exists, use the next representable value above maximum calibration score (predict none). A single global threshold is deployed unchanged across languages. Calibration is never used to select direction or prefix parameters.

Held-out ROC-AUC, TPR at FPR <=1%, achieved FPR and diagnostic ROC thresholds are under **`heldout_diagnostic_roc_only`**. These held-out-label diagnostics never alter the deployed calibrated threshold, reported separately with actual held-out TPR/FPR overall and per language. Paired comparisons recompute metrics for ReCaLL, static SERSEM (`greybox_score`), LUMIA and saved baseline fusion on exactly the same identities; adaptive SERSEM is included on the same cohort when its exact-identity scores are attached. No new fusion is fitted. Missing, duplicate, changed or nonfinite scores fail for every attached method; no silent intersection/subsampling. No confidence interval or significance claim is implied by paired metric differences.

Full reports exact 1000/1000 coverage. Smoke reports 30/1000 original coverage and 30/30 selected coverage, preliminary status and empirical low-FPR resolution. Per-language reports use the same global calibrated threshold. Saved comparison methods retain their original baseline spans: if positional limits shorten ReCaLL's span, the comparison is still paired by identity but does not imply identical spans across methods. Both ReCaLL branches always match each other.

Artifacts in OUT:

* `config.json`: complete scientific/execution identity and input file hashes.
* `metrics.json`: coverage, paired metrics/differences, calibrated results, diagnostic ROC, limitations.
* `recall_scores.parquet`: all selected rows, both mean LLs, ratio, exact identities, span hashes, truncation counts and prefix provenance.
* `matched_comparison.parquet`: held-out exact identities, all five scores, calibrated ReCaLL predictions.
* `run_manifest.json`: completion status, counts, selection/pool/source/config and artifact hashes.
* `prefix_manifest.parquet`: one source prefix per selected sample with exact 128 IDs/hash/provenance.
* `recall_cache.sqlite`: resume-safe plans and branch results.
* `source_version_hashes.json`: upload source hashes, versions and scoring identity hash.
* `threshold.json`, selected partition snapshots, `input_paths.json`, model-cache setup and resource logs.

The upload itself contains `recall_code_attack/source_manifest.json`, verified against a notebook-pinned SHA256. No baseline notebook or source is rewritten by the packaging script. Rebuild the ZIP after any ReCaLL source/test/README changes; its notebook pin updates automatically.
