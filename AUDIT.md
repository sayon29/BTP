## Reconstructed Section 2.1: exact equation and assumptions

Implementation: `shared/weighted_anomaly.py::WeightedAnomalyMIA`. It uses only source text/language, tokenizer offsets and output logits; it requires no probes, hidden-state output, hooks, gradients or membership labels. Both components share the same GPU model/tokenizer but run separately. `BRANCHES=["greybox"]` skips original probe training/loading; `BRANCHES=["lumia"]` skips grey-box inference entirely. The shared loader constructs a LUMIA object for model/configuration reuse, but grey-box scoring never accesses its hidden features.

For tokens x_0,...,x_(T-1), raw model logits l_(t-1,v), eligible target set E, and vocabulary size V, our chosen implementation is:

```
mu_t    = (1/V) sum_v l_(t-1,v)
sigma_t = sqrt((1/V) sum_v (l_(t-1,v) - mu_t)^2)
z_t     = (l_(t-1,x_t) - mu_t) / max(sigma_t, epsilon)
p_t     = sigmoid(z_t)
a_t     = w_t / sum_(j in E) w_j
S_grey  = sum_(t in E) a_t p_t
```

This implements the paper's raw-logit standardization, sigmoid and structural weighting. The following details are **our explicit resolutions of underspecification**, not recovered author mathematics:

1. **Vocabulary statistics:** uniform population mean/variance over *all* output vocabulary entries, including special-token entries; no softmax/probability weighting, top-k restriction, sample-variance correction or vocabulary filtering. Variance and means use float32; model inference retains configured fp16/bf16. Divide by `max(std, 1e-6)` by default; epsilon and vocabulary-processing chunk size are configurable and recorded. Chunking computes per-position vocabulary moments, not sequence-wide moments, and does not avoid allocation of the model's full logits tensor. Nonfinite/out-of-range outputs and GPU OOM raise errors.
2. **Sigmoid and sequence reduction:** unit-temperature, zero-bias sigmoid before reduction, then a sum-normalized positive weighted mean. No learned sigmoid, entropy-derived multiplier, fitted scale, intercept, min-k reduction or extra length correction. The score is bounded in [0,1] and oriented higher-for-member; it is not a validated calibrated probability. The paper does not specify the final reduction/normalization denominator or numerical stabilization. Dividing all raw weights by their maximum before this weighted mean would cancel exactly, but mean-of-max-normalized-products would be a different unimplemented assumption.
3. **Causal alignment:** predictor logits at t-1 score target x_t. E excludes t=0, special-token targets and empty-offset targets. We weight the **target's** character span. Tokenizer-default special-token insertion is enabled; no extra BOS/EOS is added manually. The first token has no prediction unless preceded by the tokenizer's own special token. Entire vocabulary entries still participate in moments even when special targets are excluded. No padding/batching ambiguity: one text per pass.
4. **Truncation and offsets:** same configured first-sequence truncation as the original branch (smoke 512, full 8192); no sliding windows or document segmentation. Compute structure on full source, then project retained token offsets. Span maximum projects character weights onto subwords; special/empty offsets contribute zero. Invalid offsets or no eligible target cause errors. Character offsets are Unicode indices; AST byte offsets are converted with UTF-8 prefix decoding as upstream does.
5. **Structural base and identifier classification:** initialize every character to 0.1. Only AST node types containing `identifier` can receive standard identifier weights, so syntax/keywords are not promoted merely for matching a word regex. Whole identifiers matching upstream's ASCII `[A-Za-z_][A-Za-z0-9_]{3,}` receive 1; shorter identifiers remain 0.1 unless another rule wins. All characters of a qualifying identifier share its weight, including subwords that would fail the original LUMIA token-level regex. Node types containing `identifier` can include compound identifiers, preserving that upstream node-type heuristic. This is a deliberate reconstructed interpretation of the paper's syntax/short-auxiliary suppression, **not** the unchanged LUMIA mask.
6. **Length and literals:** long identifiers are **>=10** characters, following Table 1 despite the prose saying exceeding 10 and upstream using >10. Every AST node whose type contains `string` receives weight 5; no entropy estimator or length cutoff is invented. This differs from upstream's >15-character string heuristic. The paper names high-entropy literals without specifying an entropy threshold. Both decisions are recorded as reconstruction assumptions.
7. **Dictionary/psychological rules:** reuse upstream `ASTExtractor.split_identifier` and its en_US dictionary; count unknown words of length >=4, flag when at least one is unknown and unknown_count / all_split_words >=0.5. This ratio and ASCII splitting are upstream heuristics, not specified in the paper. Flagged identifiers receive 10. Reuse the case-insensitive TODO/FIXME/HACK/“Note to self” substring regex (no added word boundaries), raising matched spans to 10. These dictionary checks are actually reached because the reconstructed branch passes language.
8. **Linting/overlap:** reuse upstream `LinterExtractor.extract_errors(text, language)`: all returned flake8 diagnostics for Python (not a new selected-code list), generic formatting fallback when Python has none or for other languages. A diagnostic boosts offsets [-2,+3) around its position to at least 5. Match the upstream flake8 invocation without isolating its external config; environment-level flake8 settings can therefore affect scores and must be reported. Every overlapping signal uses **maximum** weight, including comments versus strings, rather than upstream fallback assignment order. This precedence is our resolution of ambiguity.
9. **Parsing/errors:** use the pinned five tree-sitter parsers and source-node traversal. Tree-sitter error/partial trees retain their available structure; `greybox_ast_has_error` records this per sample. Missing parsers, dictionary, flake8, unknown languages and invalid diagnostics fail explicitly; no silent regex-only replacement. Parser node recognition is syntactic, not a claim that all language literal forms are recognized as strings. No new native linter is introduced for non-Python languages.
10. **Standalone provenance/checkpoints:** no grey-box parameter is fit using membership labels. Each actual GPU result is cached atomically by source hash, language and complete configuration (which includes algorithm source hashes, versions and these fixed implementation semantics). Saved scores include eligible-target counts and AST-error flags. No fabricated cache entries, scores or probes are created locally.

The original LUMIA branch is **not** retrofitted to share this reconstructed mask: its original language omission, >10/>15 boundaries, token-level fallback and pooling stay intact. Thus both branches represent their stated source/method provenance; the reconstructed branch is not a pure output-head ablation with identical masks.

## Our fusion experiment and leakage boundary

No accessible author fusion rule was recovered. `fit_fusion`, `add_fusion` and the notebook implement **our** optional convex combination:

```
S_fusion = alpha * S_lumia + (1 - alpha) * S_grey
```

Both raw component scores are already bounded; there is no scaling, fitted intercept, per-language coefficient, sigmoid after combination or test-set direction flip. The configurable default is **fixed alpha=0.5**, a prespecified experiment requiring no label fitting. An alternative `fit_grid` chooses alpha by maximum AUC on the separate fusion pool, using the recorded default grid {0,0.1,...,1}. Ties go first to proximity to prespecified alpha, then to smaller alpha. Grid endpoints are allowed and may select a single component. Neither this formula nor grid-AUC optimization is attributed to the authors.

Data flow is official train → 80% shadow / 20% calibration pool; calibration pool → 50% fusion fitting / 50% threshold calibration, stratified by language and membership. Shadow → unchanged upstream 60/20/20 fitting/stopping/layer selection. Official test stays held out throughout. Content hashes are deduplicated and cross-role overlap rejected. Probe compatibility checks protect the **entire** calibration pool and held-out data from training overlap.

Full counts: 25,000 shadow, 3,125 fusion-fit, 3,125 threshold-calibration, 25,000 held-out. Smoke: 160, 20, 20, 100. Fitting halves may differ by one within a stratum when counts are odd. Alpha and fitting provenance/grid diagnostics are saved in `fusion.json` before threshold selection. A threshold per reported branch is chosen solely on threshold-calibration at empirical FPR <=1%, then saved in `thresholds.json` **before** any held-out scoring. Final held-out AUC/TPR metrics and distributions are reported separately for original LUMIA, reconstructed grey-box and experimental fusion. ROC TPR@<=1% is descriptive, not a threshold optimization used in deployment. Smoke has inadequate low-FPR resolution. `metrics.json` prevents repeated completed evaluation in the same run directory; user changes need a new run ID and must not be motivated by held-out tuning.

## Actual entry path

1. `run_pipeline.sh` sources the tracked `.env`, defaults to 3B, 5,000 samples per language and bf16, then checks/downloads **3B** `probes_bigcode_starcoder2-3b.pkl`. A download failure exits the shell script; the README's promise of subsequent automatic training on that failure is inaccurate. Other model names are symlinked to that same probe, which is unsafe/incompatible for 7B.
2. It invokes `code/run.py`. The only registered attack is `lumia`. The Python CLI default is **10,000** samples per language, unlike the shell default of 5,000. The runner loads each language config's `test` split, assumes `content` and `membership`, samples equally by class, then splits per language/class in half if probes are absent. With a probe file, **all sampled rows become evaluation** and shadow is empty. Existence alone does not establish training/evaluation disjointness. A failed load after the existence check leaves no shadow samples for training.
3. `LumiaAttack.train_probes` extracts all layers' representations, then shuffles separately by membership label into 60% fitting, 20% early stopping and 20% layer selection. It does not stratify the internal split by language. The legacy `lumia_train_fraction` is unused. Its internal `test` is a development selection split, not the final evaluation set. Selecting layers on it means the selected layer AUC is not an unbiased final performance estimate.
4. `compute_scores_with_vectors` extracts activations on evaluation texts, calls selected probes and takes their unweighted arithmetic mean. Labels are not passed to this scoring method. `run.py` computes global/per-language AUC and saves scores, vectors, metadata and a code snapshot. There is no separate threshold calibration, TPR@1% reporting, sample ID or robust resume mechanism upstream. `plot_results.py` plots ROC and replaces missing scores by zero; our notebook does not use this imputation.

## Representation and structural signal

`MIAttack.py` is the abstract model/tokenizer/argument interface. `transformers_compat.py` supplies explicit truncation/padding, model placement and API shims. At runtime the notebook directly imports `LumiaAttack`, `ASTExtractor`, `LinterExtractor`, `MIAttack` and tokenizer compatibility utilities from the pinned checkout.

`_extract_activations` registers hooks on every transformer block, processes one text per forward pass and concatenates the ordinary sequence mean with a structurally weighted mean (dimension 2×hidden size). Token offsets map character weights to token weights using a span maximum. Weights are normalized by their maximum before pooling. Syntax/boilerplate receives 0.1, recognized identifier tokens 1, long identifiers 3, long strings 5, comments/psychological tags 10, and formatting neighborhoods at least 5. The fallback identifier regex requires at least four characters; long identifiers are strictly **>10**, strings **>15** characters.

`ASTExtractor` supports five tree-sitter parsers and en_US dictionary checks. **However**, the active `_extract_activations` call is `generate_char_weight_mask(text)` with no language, although scoring accepts languages. Thus the mask's language is `None`: AST parsing and dictionary identifier checks are bypassed, and regex fallback is used. Likewise `LinterExtractor` runs flake8 only for `language == 'Python'`, so active scoring uses generic spacing/mixed-indentation regex instead. Installing AST/Enchant does not change that call path. Language forwarding is intentionally not patched in the original LUMIA branch. The separate reconstructed grey-box branch passes language explicitly; it does not claim numerical equivalence to this active LUMIA mask.

The model produces logits as part of its forward pass, but they are discarded in this branch. There is **no active token logit Z-score/sigmoid scalar, independent anomaly score, or fusion of such a score with probes**. `WeightedAnomalyMIA.py`, `NeighborhoodAttack.py` and `MetaEnsembleAttack.py` appear only as optional snapshot filenames; they are absent. Loss/Min-K/PAC live in a separate `baselines/` runner and are not the SERSEM ensemble.

## Probe training, persistence and failure behavior

`LinearProbe` is actually an MLP: input → 128 → ReLU → Dropout(0.5) → 1 → sigmoid. Each layer uses Adam (lr 1e-3, weight decay 1e-4), BCE, batch size 32, up to 100 epochs. Validation AUC is checked every five epochs, patience five such checks. `best_state = probe.state_dict()` lacks a deep copy: subsequent fitting can mutate the supposed early-stop snapshot. We preserve this behavior. The top five layers by the separate development selection AUC are averaged; no learned fusion weights exist.

The pickle stores state dictionaries, best/ensemble layers, activation dimension, number of layers and positional internal split indices. The loader does not establish model revision, training contents, dataset revision, checksum, context/precision compatibility or independence from current evaluation data, and does not enforce its saved layer count. The checkout contains **no probe pickle**, despite the README tree listing one. The remote HF probe provenance and numerical compatibility remain unverified. The shell's 3B-for-7B symlink is not reproduced.

Upstream returns random membership scores when probes/layers are missing and substitutes zero activations on extraction errors, including potential OOM. Those are unacceptable for a baseline. The external wrapper requires compatible trained/verified probes, detects upstream extraction error logs, checks finite shapes, removes leftover hooks, and raises. It never creates synthetic scores, probes or zero-feature substitutes. Success-path upstream calculations/training logic are unchanged. Feature chunks are atomically cached; after training, unused layer feature arrays are discarded outside upstream because only the selected layers contribute to scoring. No pooled-feature arithmetic is changed.
