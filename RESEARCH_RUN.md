## 2. Standalone neighbourhood notebook

Upload `notebooks/02_sersem_neighbourhood.ipynb` and attach `neighbourhood_kaggle_source.zip` (both small source ZIPs contain the same allowlisted research helpers). Start in a fresh GPU kernel. Set **BASELINE_RUN** to the exact saved notebook-01 directory containing config.json and heldout_test_manifest.parquet. Use the existing **1,000-sample** manifest and completed saved LUMIA, grey-box and fusion scores. Set BASELINE_SCORES to that final held-out score Parquet; the notebook validates coverage and identities before inference. Do not retrain LUMIA or StarCoder2.

Reuse the same target cache. The notebook checks the saved API/numerical package versions against the current environment before comparison. No second target identifier/revision, context, precision or seed is chosen: these are inherited from SERSEM. Set SOURCE_ACCESS/caches to the same pinned source data. The notebook reads original source rows by the saved IDs/hashes; it never resamples a new held-out set. Smoke uses a clearly identified balanced 30-row subset (3 per language/class); full requires exactly 1,000 rows and evaluates every ID in the **saved** manifest. A different-size manifest fails rather than being trimmed or resampled.

Default **K=5**. Set `SITE_IMPORTANCE="sersem"` to reuse the existing structural weighting implementation exactly, or `"uniform"` for the previous uniform-within-kind site policy. Missing exact-weight dependencies fail rather than invent weights. See [neighbourhood_attack/README.md](neighbourhood_attack/README.md) for importance aggregation and smoke/full settings. K=1/3 remain separate optional experiments. Set NLL_REUSE_FROM to a prior compatible neighbourhood output directory to import exact scalar NLLs across K runs; target/revision/context/dtype/code/version checks must agree. Generation/results remain separate; no original NLL is recomputed when its valid record is present. The code-aware MLM is [microsoft/codebert-base-mlm](https://huggingface.co/microsoft/codebert-base-mlm), which Microsoft documents for mask prediction, unlike plain codebert-base. It resolves an immutable revision on Kaggle and validates loading information for missing/random MLM head tensors. No MLM checkpoint was downloaded or validated by GPU execution locally. MLM downloads are explicitly enabled by its setting on Kaggle only; allow roughly 0.5 GB additional cached weights and check free disk. Set MLM_LOCAL_FILES_ONLY=True once cached/attached. The proposal model uses a bounded ≤512-token context; **StarCoder2 scoring still inherits the original 8192 cap**. MLM proposals are float32; target dtype is inherited, never silently reduced.

By default both neural models execute on GPU, but CodeBERT weights are parked in CPU RAM between generation chunks, releasing its GPU memory before long target forwards. This is storage placement, not CPU inference. Target batch size defaults to 1; MLM batch size 4; source chunk size 32. All are explicit settings. Larger target batches need measured capacity; no automatic OOM fallback is used. Changing a batch/path setting on resume is allowed and recorded; model/formula/cohort/precision/context/K/source-version changes require a new run. Padded-batch kernels may introduce rounding differences; batch=1 is the reproducibility default.

Perturbations prioritize eligible spans by the maximum overlapping SERSEM target-token weight across affected occurrences, with seeded tie shuffling. The weights are those of the existing Section 2.1 reconstruction, not recovered author weights. Insertion has no original span and receives selection priority zero. Generation tries one neighbour per site first, then revisits productive sites round-robin to reach K distinct neighbours. Each neighbour makes one logical transformation of the original, using an MLM proposal. Conservatively constrained Python function-local variable renames are available; they exclude calls, attributes, nested scopes, defaults/decorators/annotations, reflection and binding collisions, replace all scoped Name occurrences, and compare normalized Python ASTs. Other languages do not rename identifiers. Optional `ALLOW_COMMENT_INSERTION=True` permits a plain MLM-word comment on a blank line/at EOF, with syntax and noncomment-token checks; this is an explicit neighbourhood generation policy, not SERSEM. Keywords are never used as renamed Python identifiers. Original syntax errors, directives/doc-comment/cgo hazards, unchanged truncated target inputs, insufficient distinct proposals and other failures are recorded. No original-text substitute or smaller K is silently used.

These checks preserve ordinary parsed code structure; they are **not a proof of behavioral equivalence** for programs that inspect source or for every compiler/external tool. Tree-sitter validity also does not establish type correctness. Original parser-invalid rows cannot be silently repaired while claiming unchanged semantics. Transformation provenance and failed attempts are saved for audit. Treat any incomplete coverage as a limitation of this conservative attack.

Each original and neighbour is scored with causal alignment `logits[t] -> input_ids[t+1]`, excluding first/unpredicted and padded tokens, and dividing NLL by the actual valid target count. Cross entropy is float32 in bounded logit blocks, with float64 sum accumulation. Default add_special_tokens=True and the inherited truncation policy are recorded. No target hidden states, LUMIA probes or hidden activation extraction is loaded. The score is exactly **mean K neighbour normalized NLLs − original normalized NLL**; larger means more member-like. Original NLL is committed once per unique text/target/math identity and reused on restart. Generated full neighbour text, metadata/failures, neighbour NLLs and results are compressed/checksummed in SQLite. Failed rows have no invented attack score.

`runtime.json`/`runtime_history.jsonl` record measured generation+NLL+I/O throughput, actual target forward batches/texts and tentative remaining ETA. Default target work is up to K+1 calls per successfully perturbed original at batch=1; generation uses additional measured MLM work. This is a count, not a throughput claim. Disk grows with compressed neighbour content and K; inspect the 500-attempt checkpoint before completing all 1,000 examples.
