The runtime preflight reads the **pinned actual config**, counts cached weight files, inspects free capacity and writes current measurements. Model configuration reference: [official config](https://huggingface.co/bigcode/starcoder2-3b/blob/main/config.json).

Preflight budgets missing active feature space, remaining text cache, a 0.35 GiB metadata-index allowance, 0.20 GiB checkpoint/staging allowance, missing weight downloads (only if explicitly enabled), and the default 1 GiB disk reserve. Available-RAM warnings and guards do not guarantee allocation success.

## Fidelity and experiment separation

`FAITHFUL_MODE=True` requires fp16 model execution, the 8192-token reference cap, float32 pooled storage and upstream attention selection. Original tokenization/truncation code, mean/structural pooling, weighting heuristics, MLP, optimizer/epochs/early stopping (including the upstream shallow best-state behavior), label-stratified 60/20/20 internal roles, layer selection and top-five arithmetic mean are preserved. Extraction calls the original method one text at a time, allowing its discarded logits to die between forwards. All original hooks/pooling still execute; only pooled outputs for the active group go to disk. Unused KV output caching is explicitly configurable and disabled by default; no past states are consumed. Faithfulness describes mathematical operations, **not demonstrated bitwise equivalence** across CUDA/library versions or chunk layouts.

`MAX_LENGTH`, `DTYPE`, `FEATURE_STORAGE_DTYPE` and `ATTENTION_BACKEND` are explicit settings; reductions/overrides require faithful=False and a new run ID. There is no implicit approximation or OOM fallback. Grey-box output-logit population Z-score, sigmoid, float32 chunk reduction, epsilon, token eligibility and structural weighted mean remain unchanged. Logits are not persisted; chunking vocabulary-moment reduction does not change the existing score equation. Fusion remains our fixed/grid-selected convex mixture. Fusion weights use fusion_fit only, thresholds use threshold_calibration only, and held-out metrics are computed after both are frozen.

Standalone branches share the same pinned source row IDs, hashes, seed and manifests for identical sampling settings. Grey-box-only skips probe training/features. Fusion-only computes both constituent scores but reports the configured fusion branch. Hashes and explicit identity/official-split checks prevent role overlap. Configuration/dependency/source fingerprints reject incompatible reuse. Prior smoke/legacy artifacts cannot silently become new resource-run checkpoints.

### Can all layers be extracted in one pass?

**Verified source: yes, they already are extracted together for each file.** Upstream immediately pools each layer to `concat(mean, weighted_mean)` on CPU. At float32, all 30 pooled vectors need **0.703 MiB per file** or **5.625 MiB for an eight-file chunk**, excluding temporary stacking copies. Hooks do not require retaining every token's hidden state for every layer. Do not replace these hook outputs with a generic `output_hidden_states` tuple: hook boundaries, final normalization and indexing may differ, and retaining raw states wastes memory.

**Theoretical storage constraint:** Unchanged offline probe training eventually needs each complete layer's sample matrix. Float32 features cost `N × L × (2h) × 4` bytes. For N=25k, L=30, h=3072 this is 17.166 GiB irrespective of sharding. One streaming extraction pass can write all layers to bounded chunk buffers and layer memmaps without holding all features in RAM, but **not to 5.3 GiB of free local disk**. An online per-chunk probe trainer would change permutation, optimizer trajectory and stopping, and is excluded. Keeping the entire matrix only in a temporary RAM filesystem is still RAM storage and is not a durable-disk solution.

All rows additionally need model weights, transient logits/attention/pooling, native parsers, metadata/score stores, probe tensors and checkpoints. Disk-four/RAM-26 is a **combined storage tier**, not elimination of the feature information. It answers the request without keeping all layers in RAM or exceeding feature disk allowance, but it requires ~14.9 GiB *available host headroom* and an explicit memory guard. Float32 preallocated writes avoid `vstack` doubling an experiment-wide array. Original layers must still train in order, on the original complete train/val matrices and saved RNG trajectory. At most one layer's host staging/train/selection copies are needed at a time. Feature staging is allocated **after** model loading to avoid overlapping load peaks.

More disk, verified lossless compression, hybrid/RAM staging, or an explicitly different sample-size experiment are the available tradeoffs; there is no generic lossless streaming trick that removes the storage need while retaining the unchanged trainer.

No setting was changed by this audit.

For research, RAM features cannot be assumed to survive a session: preserve completed probe states/RNG and durable disk layers; after restart re-extract missing RAM layers once over the shadow pool, then continue original-order fitting. ### Can LUMIA and grey-box share a forward?

**Proposal, mathematically feasible subject to checked input equivalence:** Pool original LUMIA hooks during the causal-LM call, reduce that call's logits with the existing grey-box population-Z-score/sigmoid/weighted-mean equation, then discard logits. An external model-output hook or adapter can observe the original call without changing the upstream checkout; it must detach/reduce promptly, not retain output tensors across files. Both methods consume the same causal computation and need no extra transformer pass when actual inputs agree. MLP/top-five inference occurs afterward on the original pooled values.

Do **not** share the structural mask: LUMIA currently calls `generate_char_weight_mask(text)` without language, hence its regex/generic path; grey-box uses its own language-aware AST/dictionary/linter reconstruction and different token eligibility/normalization. Its AST mask cannot replace LUMIA's mask while claiming unchanged upstream semantics.

Before sharing, compare the actual input IDs, attention masks, special-token insertion, truncation side/cap, positions and any additional model inputs. Upstream `tokenize_with_truncation` requests padding and may set/add a pad token; grey-box tokenization explicitly requests special-token/offset masks. Single-text StarCoder2 encodings are expected to agree, **not statically proven for every text/tokenizer**. Keep separate branch weights/offsets/target shift, original floating dtypes, reduction order and epsilon. If inputs differ, use explicitly counted separate calls or fail the proposed joint mode; never silently reuse different logits. New/shared reducers require Kaggle comparisons to standalone outputs before adoption, without changing fp16/backend/context to force a match.

For F+C+H=31,250 files, joint scoring reduces **62,500 to 31,250** target calls; joint validation reduces 16 to 8. Combined with single-pass shadow features the count becomes **56,258**, a **78.57% reduction in target-call count** from 262,516 (not a measured wall-time speedup). ### Other avoidable overhead and fidelity guards

**Verified source and proposals:**

- **LUMIA preprocessing repeats eight times per training file:** regex/generic structural analysis, full-text masks and tokenization are recomputed on each group pass. LUMIA does *not* repeatedly parse language-specific ASTs in this path because no language is passed. Grey-box parses once per uncached scored file, with global parsers/dictionary reused; its validation scalar cache avoids repeating an already-scored file. Cache branch-specific derived masks/tokens by content hash, language, tokenizer/model fingerprint, cap and preprocessing/native-tool versions if repeated group passes remain. Never merge distinct branch semantics. Exact dictionary lookups can use a bounded in-process memo.
- **Grey-box UTF-8 offset work:** `char_weights` decodes each byte prefix twice for every AST node. This can grow superlinearly for large files. A reusable byte-to-character index preserving replacement-decoding behavior and node-overlap/max rules can remove avoidable scanning; it needs equivalence checks on multilingual files. The HF viewer exposes very large source lengths, so full-file preprocessing can dominate even when GPU tokens truncate. Clipping structural analysis to a token prefix would change the current full-file semantics and is not proposed as a silent optimization.
- **Dataset reading:** `SourceStore.batches` enumerates each source split until selected rows are found, even in cached Arrow mode. Eight feature passes plus validation and separate F/C/H score invocations repeat decoding/scans. Its 0.25 GiB compressed text cache helps only rows that fit. In cached mode, use original `source_row` indexes to retrieve selected Arrow rows in bounded batches; preserve sample/hash ordering. For streaming, a bounded selected-source artifact/index can help only if storage permits and its provenance is pinned. Competition should read its mounted manifest/files directly and skip development-source scanning altogether.
- **Linter/subprocess behavior:** LUMIA's missing-language path uses generic checks. Grey-box Python can launch flake8 once per file; Python native-linter results/fallback semantics, dictionary and grammar versions matter. Reuse exact cached results; do not replace subprocess diagnostics with a cheaper approximate heuristic. A timeout or bypass is a changed failure/score policy and requires separate review.
- **Unused vocabulary projection during feature-only training:** upstream calls the complete causal LM even though it discards logits. A validated architecture-specific external backbone-only adapter could retain exactly the same decoder-block hook values while avoiding the unused output-head projection/logits allocation. This is a proposal inferred from the discarded-output source path, not verified support for any `logits_to_keep` option in the pinned library. It must prove identical inputs, normalization/block boundaries and pooled values, preserve RNG, and be disabled whenever grey-box logits are required. Target-call count is unchanged, but GPU work and peak memory could fall. No base-model substitution is implemented or assumed portable to the unknown target.
- **Hooks and transfers:** per-text `safe_extract` registers/removes all hooks and captures per-file progress output; upstream copies 30 pooled tensors to CPU with potential synchronization. A persistent external hook lifecycle and bounded batched/asynchronous transfers could reduce overhead while preserving pooling/copy completion, but require equivalence/failure-cleanup validation. During final scoring only the top-five pooled vectors are consumed; suppressing unused pooling/CPU transfers via an external adapter is an optional later optimization, never pruning transformer layers or changing selected outputs.
- **SQLite and file I/O:** `ScoreStore` opens a connection for every get/put and commits each record; feature maps flush every eight samples; probe checkpoint pickle envelopes serialize/copy saved states every layer. Use scoped connections, chunk transactions, compact cached-record queries and safe coalesced flushes after review. Preserve atomic commit/resume integrity. Avoid recomputing all-record progress counts every chunk. Measure CPU/I/O overlap and contention rather than presuming GPU is always busy.
- **Fusion/calibration:** the fixed-alpha F-score pass can be skipped exactly. Predeclare/freeze parameters from disjoint development pools; a final competition scorer should only load them. Emitting continuous scores does not require local hidden-label threshold fitting or plotting. This eliminates evaluation-time calibration work, not the original research calibration protocol.
- **Batching and kernels:** current feature/scoring chunk sizes bound storage/MLP work, but the transformer still runs batch=1. Length bucketing with correctly masked pooling might improve utilization, but upstream single-file means include all its sequence positions; naive padded pooling changes scores. Masked variable-length batching, attention overrides, TF32/quantization, altered precision or context are not presumed faithful speedups. Keep the original mode until separately approved/proven; do not count a chunk of 32 as one model call today.

### Stage 2 portability blockers identified in source

1. **Loading and identity:** notebook MODEL_ID/revision resolution uses HfApi; `cached_weights` looks up Hub shard indexes; probe names/identity use the HF model ID and immutable revision. An arbitrary organizer directory is not a Hub repository. `MODEL_CACHE_DIR` existing-smoke assumptions do not locate supplied assets. The target adapter needs a local artifact fingerprint/config path without online lookup, while retaining strong provenance.
2. **Hardcoded load heuristic:** `build_attack` requires 9 GiB free if the ID string contains `3b`, otherwise **19 GiB**. A perfectly valid supplied 3B path without that substring would fail on a T4 before loading. The unknown target fitting the reference accelerator does not justify either threshold.
3. **Architecture discovery:** upstream special cases `transformer.h` and `model.layers`; its generic fallback can collect nested attention/norm children instead of decoder blocks, and has a default layer count of 24. Checking returned list length alone cannot establish correct hook boundaries. Need external architecture adapters with validated block order/output semantics; config aliases (`hidden_size`, `num_hidden_layers`, `vocab_size`) are not universal.
4. **Probe width and representation:** runtime expects `2*model.config.hidden_size` and float32 LinearProbe input. Published/trained 6144-wide weights cannot accept other widths; equal widths still have unrelated feature bases/scales. Best/top-five layer indexes and selection AUCs belong to the training model, not another decoder. Models with fewer than five layers need the documented min(5,L) policy; malformed/absent layers must not trigger original random/zero fallback.
5. **Tokenizer:** fast offset support is required by both structural mappings but is not guaranteed by the task. Padding/special-token insertion, BOS/EOS, zero-width offsets, Unicode/byte indexing and additional input keys may differ. `ensure_pad_token` can add a new token without resizing embeddings; do not mutate an unknown tokenizer/vocabulary implicitly. Vocabulary-based score moments still use all actual output-logit vocabulary entries.
6. **Context:** faithful research mode hard-requires 8192 although supplied model capacity can differ. A declared per-model context policy must read supported config/positional/RoPE constraints, rejecting sentinel tokenizer limits. Capping at min(reference cap, verified supported capacity) changes the evaluated token population and must be labelled explicitly; it is not current 8192-reference reproduction. No silent truncation adaptation.
7. **Dtype and activation fit:** fp16 model/reference and float32 pooled storage are current choices; T4 lacks native bf16 suitability. A different target may require another supported precision or have very different activation/workspace footprints. Fitting model weights is not proof of fitting attack forwards, original training tensors or full logits. No automatic quantization/offload should be introduced to claim compliance.
8. **Forward/hook outputs:** tuple-first hidden output assumptions, `model.device`, single CUDA device mapping, `output.logits`, kwargs `use_cache`/`return_dict`, hidden width uniformity and pre/post-final-normalization positions need capability checks. A newer architecture may not load in pinned Transformers 4.52.4; the provided environment and dependency contract must be verified, not replaced wholesale.
9. **Pretrained probes and fusion:** current manifest checks rightly reject a new target identity. Target-specific fitting on allowed Stage 1 development labels could recreate original probe math inside the budget, but transfer quality/label interpretation is unmeasured and no Stage 2 evaluation labels may be used. A Stage 1 alpha/threshold is allowed as a fixed parameter but its transfer quality is unknown. Never silently disable LUMIA/reweight fusion when probes fail.
10. **Branch coupling:** even grey-box-only calls `build_attack`, constructs LumiaAttack and validates decoder-layer discovery. Grey-box mathematics itself needs logits/token offsets, not hidden probes; a future separate target loader should remove this accidental architectural dependency without altering its equation.

Pretraining and public attachment are **permitted**, not a solution to model-specific representation incompatibility. A genuinely fresh dual-branch entry needs affordable target-specific probe fitting or a separately reviewed transfer mechanism; no universally portable exact LUMIA hidden-state probe exists in the current artifacts. A standalone grey-box entrant is a possible separately declared alternative after tokenizer/context capability validation; it must not be presented as unchanged full SERSEM/fusion. No choice of fallback/transfer method is implemented here.

### Concrete optimization/compatibility plan for review

Priority is based on removing whole target forwards before tuning CPU/I/O details. These are planned changes only.

1. **Freeze the competition contract before implementing its adapter.** Obtain numeric per-stage budgets, reference accelerator/count and memory/storage, network policy, literal target/manifest paths, output schema, permitted development resources at rerun, and required public asset declarations. Pin actual 2027 data schema/counts/IDs; resolve the viewer/spec discrepancy. Keep the legacy research baseline and its splits/provenance intact. Acceptance: a documented input/output/resource contract with unresolved fields filled, no invented Kaggle defaults.
2. **Prefer a single shadow extraction pass using measured hybrid storage** on the stated 31.35 GiB RAM / 5.3 GiB free disk machine. Use original per-text upstream pooling, chunk writes to four disk layers plus 26 float32 host arrays; original-order unchanged probe fitting; free layer arrays after committed probes. Add allocator/RAM checks and explicit rebuilding of volatile features on restart. If more durable disk is available, use all-layer layer-wise memmaps. Separately validate avoiding the unused LM vocabulary head in feature-only forwards; keep the exact original hidden/pooling operations and do not skip it when logits are consumed. Acceptance: standalone pooled vectors/probes/top-five agree on a fixed development run; source IDs and original split/RNG sequence unchanged; peak RAM/disk fit. G=6 is an interim existing setting if preflight permits, reducing shadow calls by 37.5% but not solving single-pass extraction.
3. **Add joint LUMIA/logit scoring with strict input-equivalence checks.** Reuse one model object/forward; compute original pooled vectors and reconstructed grey score; maintain independent outputs and explicit call counters. Acceptance: standalone/joint inputs and scores agree across all languages, Unicode and length cases; same grey reduction equation/dtype/order; no retained cross-file logits; incompatibility is explicit. Together with step 2 this removes ~78.6% of current cold target calls, not necessarily 78.6% wall time.
4. **Remove provably unused work.** Skip F-pool inference for prespecified alpha; keep grid fitting separated. Design the competition scorer to load frozen allowed parameters and score only manifest files without local labels, plotting, sampling, full-source overlap scans or repeated resource probes. Read the supplied target once from its path. Acceptance: all manifest IDs receive one finite continuous score in organizer schema, no evaluation labels needed, a clean fresh execution completes without manual state.
5. **Address Stage 2 probe feasibility explicitly.** Preserve model identity guards. Decide after review whether a dual-branch submission can afford original target-specific fitting within budget on allowed development data; otherwise record that the unchanged pretrained dual pipeline cannot be guaranteed to transfer. Do not resize probes, map arbitrary layer indexes, drop branches or substitute a new method silently. A separate grey-box-only entrant or transfer method needs its own declared review. Architecture/path/tokenizer/context adapters remain necessary even for grey-box-only.
6. **Then optimize repeated CPU/I/O work exactly.** Direct indexed Arrow reads for research / manifest reads for competition; bounded immutable branch-specific token/mask caches; exact UTF-8 index acceleration; scoped SQLite transactions; safe persistent hook/transfer lifecycle; reduce unused selected-layer pooling work only after equivalence review. Expose timing/counters for tokenization, weights, lint, model, pooling/logit reduction, probe fit and I/O. Defer variable-length transformer batching/kernel changes until exact single-file parity is demonstrated; no lower precision/context or optimizer change is included.
7. **Measure before committing to full scale or submission.** On Kaggle only, run fresh-start stage timings and representative length-stratified development samples plus full-cap stress cases. Measure allocated/reserved GPU peak, RSS/available RAM, disk growth, tokens/second, effective model calls/second and GPU idle/preprocessing time. Then run one intermediate end-to-end original MLP experiment, joint/standalone parity, research stop/restore parity, and a completely fresh manifest-only rehearsal with the actual attached assets. Preserve train/calibration/test separation throughout and do not tune using hidden evaluation feedback. Accept only if measured `T_setup + T_source + T_features + T_probe + T_score + T_output + margin <= B` at required coverage; model-fit alone is insufficient.

The current research code remains usable for its documented legacy protocol; it is not yet evidence of competition runtime compliance. Major runtime/storage/submission changes above await plan review. Neighbourhood and adaptive attacks remain outside scope.
